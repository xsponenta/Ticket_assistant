## Text cleaning and PII masking (D5)

`clean_description()` = Jira wiki markup → Markdown, then PII masking, then whitespace normalisation:

- **Code blocks:** `{code}` / `{noformat}` become fenced blocks (language kept). Code is protected while the rest is converted.
- **Headings and quotes:** `h1.`–`h6.` → `#`…`######`; `{quote}` and `bq.` → `>`.
- **Links:** `[text|url]` → `[text](url)`; `[url]` → `<url>`.
- **Inline:** `{{mono}}` → `` `mono` ``; `{color}` tags are stripped.
- **Extras:** Jira `#`/`*` lists → Markdown lists, table header rows, images, and Jira editor artifacts (see `decisions.md`).
- **Summaries:** PII masking and whitespace normalisation only.
- **Tests:** 20 test cases built from real snippets are in `tests/test_clean.py`.

**a. Classification test.**
- Test split, at most 100 per class. Available in test: bug 806, feature 1149, task 269, idea 24.
- Labels: `target_class` (issue type → D1) and `components` (Jira).

**b. Duplicates.**
- A Jira `Duplicate` link is treated as **undirected**: the later-created issue of a pair is the query, the earlier one is gold (a user writing a new ticket must find the existing one).
- Both issues must be in the main dataset. The corpus is the main-dataset issues created before the query, so gold is always retrievable.

## Doc chunks

- **Input:** Spark 4.3.0 docs, 245 pages; skipped 404, README; 243 pages chunked.
- **Cleaning:** front matter stripped (title kept); Liquid tags and `include_example` lines removed; `{% highlight %}` blocks turned into ``` fences.
- **Splitting:** on headers of any level, outside code. Each chunk is prefixed with `title > header path`.
- **Size:** target 300–500 tokens (tiktoken cl100k_base, counted on the final chunk text).

| Chunks | Tokens total | min | p10 | median | p90 | max | < 300 | 300–500 | > 500 |
|---:|---:|---:|---:|---:|---:|---:|---|---|---|
| 2,034 | 763,422 | 10 | 202 | 409 | 490 | 500 | 23.1% | 76.9% | 0.0% |

Chunks under 300 tokens are short pages, or short sections followed by a section too large to merge with.
Small trailing chunks are first merged into the previous chunk of the same page when that stays within 500.

## Notes and limitations (accepted)

**Scope candidates: top-up from val.**
- The test split has only 23 resolved feature/idea issues with a description in the Not A Problem / Invalid bucket.
- The remaining 2 were drawn from val (field `split` in `scope_candidates.jsonl`).
- All other buckets come entirely from test.

**Simulator candidates: thin classes.**
- Only 24 task and 15 idea issues in test have ≥ 80 words.
- These two classes therefore get 15 from a small pool, so the later LLM selection has little to choose from.
- Bug and feature have 135 and 227 eligible issues.

**Token counts are a proxy.**
- Chunk sizes are measured with `tiktoken cl100k_base`, not the tokenizer of the model that will consume the chunks.
- Counts for other tokenizers typically differ by about 10–20%, so the 300–500 target is approximate.
